# 浏览器端推理测试与部署说明

## 2026-07-13

## 1. 自动化验证

### 前端

```powershell
cd frontend
npm test
npm run build
```

当前覆盖 6 个纯函数用例：两种 YOLO 输出布局、letterbox 坐标恢复、类别 NMS、非法输出形状和连续命中状态机。生产构建只生成一份约 24 MB 的 ORT WASM 资源，不复制其他运行时变体。

### 后端

```powershell
cd backend
mvn test
```

集成测试覆盖鉴权、模型清单与缓存头、图片结果入库、实时指标、实时证据事件和重复事件去重。后端依赖中不存在 ONNX Runtime、OpenCV 或 WebSocket starter。

## 2. 浏览器端到端结果

使用本机 Chrome 和 Docker 生产镜像执行真实 `ruikang.onnx`：

- 图片质检：模型下载、SHA-256 校验、结果图生成和后端入库均成功；生产镜像下 WebGPU 单张推理约 `135 ms`，强制无 GPU 时 WASM 回退约 `414 ms`。
- 首次完整任务：包含约 38 MB 模型下载、会话创建、预热、推理和结果上传，WebGPU 路径约 `6.6 s`，WASM 回退约 `3.9 s`；后续任务会复用会话和浏览器缓存。
- 实时质检：虚拟摄像头分辨率 `1280x720`，预览和推理解耦；生产镜像下实测预览约 `19 FPS`、推理约 `6 FPS`、延迟约 `105 ms`。
- 网络检查：实时运行期间只有每秒一次 `/metrics`，没有业务 `/ws` 连接，也没有 `/realtime/frame` 请求。

Headless 结果用于验证 WASM 兜底，不代表带独立 GPU 的演示电脑性能上限。

## 3. 本地运行注意事项

- 首次启动会下载约 38 MB 模型并执行一次预热，按钮会显示当前加载阶段。
- 模型按 SHA-256 和 ETag 缓存；模型文件变化后清单哈希变化，浏览器自动获取新版本。
- 开发与生产都从 `/ort` 提供同一组线程版 ORT `.mjs` 和 `.wasm`，避免两种环境使用不同的初始化路径。
- 端口被占用时可以使用 `npm run dev -- --port 5174`，开发代理会清除转发的 `Origin`，不会因端口变化触发后端 CORS 拒绝。

## 4. Docker 部署

```bash
cd /opt/ruikang
cp .env.example .env
# 编辑 .env 后执行
docker compose up -d --build
```

检查：

```bash
docker compose ps
docker compose logs --tail=100 ruikang-backend
curl -I http://127.0.0.1:20080/
```

前端容器 Nginx 已设置：

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
Cross-Origin-Resource-Policy: same-origin
```

Nginx 还会把 `/ort/*.mjs` 以 `application/javascript` 返回，并把 `.wasm` 以 `application/wasm` 返回。不要删除 `frontend/nginx.conf` 中的 `.mjs` 规则，否则生产环境会停在模型初始化阶段。

宿主机 Nginx 继续反向代理 `127.0.0.1:20080`。正式域名必须配置 HTTPS；服务器不需要 CUDA、cuDNN 或 GPU 资源。
