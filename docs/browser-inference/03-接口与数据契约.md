# 浏览器端推理接口与数据契约

## 2026-07-13

## 1. 模型接口

### `GET /api/inference/manifest`

返回当前激活模型的名称、版本、SHA-256、文件大小、输入输出名称、输入尺寸、类别字典、置信度阈值、IOU 阈值和建议执行后端。

浏览器必须先获取清单，再下载模型。类别索引以清单为准，不能使用页面内硬编码顺序。

### `GET /api/inference/model?sha256=<hash>`

返回 ONNX 二进制。查询哈希必须与当前激活模型一致，响应包含 `ETag`、`Content-Length` 和私有不可变缓存指令。

## 2. 图片质检

### `POST /api/inspection/image/tasks/client-results`

请求类型为 `multipart/form-data`：

| part | 类型 | 说明 |
|---|---|---|
| `payload` | `application/json` | 模型哈希、备注和每张图片的结构化结果 |
| `sourceFiles` | 图片列表 | 原图，顺序与 `payload.records` 一致 |
| `resultFiles` | 图片列表 | 浏览器绘制的结果图，顺序与原图一致 |

单条 `record` 包含原文件名、图像宽高、预处理/推理/后处理耗时、执行策略和检测框列表。后端保存任务、记录、文件、检测框和缺陷异常；无检测框时保存为 `PASS`。

## 3. 实时质检

| 方法 | 地址 | 用途 |
|---|---|---|
| `POST` | `/api/inspection/realtime/start` | 创建实时业务任务 |
| `PUT` | `/api/inspection/realtime/config` | 更新浏览器推理阈值和命中规则 |
| `PUT` | `/api/inspection/realtime/metrics` | 每秒同步累计数量、FPS、延迟和执行策略 |
| `POST` | `/api/inspection/realtime/client-events` | 提交连续命中的检测框与证据图 |
| `POST` | `/api/inspection/realtime/stop` | 结束任务并固化统计 |

`client-events` 也是 multipart 请求，包含 JSON `payload`、`sourceFiles` 和 `resultFiles`。后端按最高置信度缺陷、位置分桶和 20 秒时间窗口去重。

## 4. 后端校验

- 模型 SHA-256 必须等于当前激活模型。
- 缺陷代码必须存在于当前启用的缺陷字典。
- 置信度必须位于 `[0, 1]`。
- 检测框必须为正面积且不能超出图像范围。
- 图片质检最多 10 张；原图、结果图和记录数量必须一致。
- 实时事件必须包含检测框，证据组数不能超过系统配置。
- 实时指标和事件只能在任务处于运行状态时提交。

## 5. 已删除协议

以下旧链路不再存在：

- `/ws/realtime/status`
- `/api/inspection/realtime/frame`
- `/api/inspection/image/tasks/upload`

前端不得持续上传摄像头帧，后端也不保留兼容推理入口。
