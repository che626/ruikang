# 浏览器端推理重构需求说明

## 2026-07-13 14:00

## 1. 目标

将实时监控和图片质检的 ONNX 模型推理从 Spring Boot 后端迁移到浏览器。摄像头预览与推理相互解耦，浏览器只向后端提交业务数据和必要证据，消除视频帧持续上传、服务端图像编解码及服务端 GPU 环境依赖造成的卡顿。

## 2. 功能需求

### P0

- 浏览器通过独立 Web Worker 加载当前激活的 `ruikang.onnx`，优先使用 WebGPU，失败时回退 WASM。
- 实时监控在本地完成取帧、640x640 letterbox 预处理、推理、阈值过滤、NMS 和检测框绘制。
- 图片质检在本地逐张完成推理与结果图生成，再提交原图、结果图、检测框和耗时到后端。
- 后端负责模型清单与模型文件分发、任务生命周期、记录入库、证据图保存、异常生成、复核和 AIGC 报告。
- 实时监控不再向后端持续发送视频帧；每秒仅同步一次性能统计，确认缺陷后才上传证据。
- 当前六类缺陷及类别顺序必须与 `data.yaml` 和模型清单一致。

### P1

- 模型下载后进行 SHA-256 校验，模型变化时自动使用新版本。
- 模型初始化、预热、推理和回退状态在页面上可见，初始化期间不得误报为运行中。
- 连续命中帧数、置信度、IOU、目标推理帧率和证据数量继续由系统配置控制。
- 客户端提交的数据必须经过后端模型版本、类别、置信度和坐标范围校验。

### P2

- 为 WASM 多线程配置跨源隔离响应头，作为无 WebGPU 环境的兼容路径。
- 保留模型管理页面与激活模型切换能力，切换后下一次初始化自动加载新模型。

## 3. 非功能需求

- 摄像头预览目标为 25-30 FPS，模型检测框在当前演示电脑上目标为 8-12 FPS。
- 同一时刻最多执行一次推理，采用背压调度，禁止推理请求堆积。
- 首次模型初始化允许出现一次预热等待；后续开始/停止实时质检复用已加载会话。
- 前端推理异常不得导致业务后端崩溃；不支持的设备应给出明确提示。
- 正式部署必须使用 HTTPS；推荐 Windows 新版 Chrome 或 Edge。

## 4. 边界

- 后端不执行 ONNX、CUDA、cuDNN 或 OpenCV 模型推理。
- 浏览器结果属于可信终端提交，后端进行格式和字典校验，但不做二次模型复核。
- 模型会被浏览器下载，不提供模型保密能力。
- 本次不改变 DeepSeek 报告内容、记录复核和缺陷分析业务。

## 5. 验收标准

1. 后端依赖中不存在 ONNX Runtime GPU 和 OpenCV，启动时不加载任何推理运行时。
2. 图片质检可在 Chrome 中完成真实模型推理，后端产生任务、记录、检测结果、文件和异常数据。
3. 实时质检启动后摄像头视频不上传；页面显示本地检测框和性能指标，确认缺陷后后端可查询到证据。
4. 模型清单返回文件哈希、输入输出、六类字典和推理配置，浏览器校验哈希后才能创建会话。
5. 前端单元测试、前端生产构建、后端集成测试和浏览器端到端检查全部通过。
